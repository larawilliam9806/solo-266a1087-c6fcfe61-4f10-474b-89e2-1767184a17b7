# 变异归一化汇总平台

同一次插入/缺失在重复序列中可能被不同样本写成不同坐标。本平台接收参考序列与
逐样本 TSV 变异文件，将等价变异按参考**左对齐归一化并去冗余**，再按规范变异
汇总多样本检出情况。

技术栈：Flask + SQLite（WAL），Docker Compose 一键启动。

## 快速启动

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

SQLite 数据文件存放在命名卷 `variant-data`（容器内 `/data/variants.db`），
重建容器不丢数据；`SECRET_KEY` 请在 `docker-compose.yml` 中替换为生产密钥。

本地开发：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
DATABASE_PATH=/tmp/dev.db flask --app 'app:create_app()' run --debug
```

## 使用流程

1. **先上传参考序列**：一条仅含大写 `A/C/G/T` 的全长序列，支持纯文本或单记录 FASTA。
2. **逐样本上传 TSV**：Tab 分隔、1-based 坐标，可带表头：

   ```tsv
   POS	REF	ALT	GT
   3	T	TT	0/1
   8	A	C	1/1
   ```

   - 仅接收：单碱基替换、带锚碱基的纯插入（如 `T>TT`）、带锚碱基的纯缺失（如 `TT>T`）
   - GT 仅允许 `0/1` 或 `1/1`
   - 每行先核对 REF 与当前参考是否一致，再做左对齐归一化
   - **可选片段参考**：若 TSV 按片段编号，上传时附上该片段的 ACGT 序列
     （按 TSV 所用链方向书写，支持纯文本或单记录 FASTA），详见下节
3. 首页按**规范变异**列出检出样本数；点详情查看各样本基因型、
   该版片段位置与方向（片段样本）以及 TSV 原记录。

## 片段坐标模式

育种测序的变异表有时按片段编号。上传或重传样本 TSV 时可附一条
**按 TSV 所用链方向书写的 ACGT 片段参考**，处理流程：

1. **定位**：在全长参考上同时查找片段的正向匹配与反向互补匹配，
   只接受**唯一的位置 + 方向组合**；无匹配或匹配不唯一时说明原因并拒绝整份上传。
2. **片段内校验**：先按片段核对每行 REF 与范围（POS 不超出片段长度），
   规则与全长模式一致，错误信息标注原文件行号。
3. **换算**：换成全长参考的正向表示。反向匹配时插入/缺失保持左锚定含义：
   左锚碱基优先取片段内相邻碱基；变异锚定在片段末端时可取**片段外相邻的
   全长参考碱基**；片段已对齐到参考起点、取不到合法左锚时拒绝该行
   （并因此拒绝整份上传）。
4. **归一化判重**：换算后沿用与全长模式完全相同的左对齐归一化与
   同一样本判重规则，因此片段样本与全长样本的等价变异会合并计数。

其他行为：

- 任何一行校验或换算失败都指出**原文件行号**并拒绝整份上传；
  同名旧样本（若有）保持不变。
- 片段序列随样本留存。**更换全长参考**时用留存的片段与原 TSV 在新参考上
  重新定位并重验；定位失败或行校验失败的样本标记为「待重传」，
  从汇总与详情中剔除，修正重传后恢复。
- 变异详情只查入库数据：片段样本显示该版片段在全长参考上的位置、
  方向（+/-）以及 TSV 原记录（片段内坐标、按 TSV 链方向书写）。
- 不附片段的 TSV 仍按全长参考坐标处理，既有库与既有流程不受影响
  （旧库首次启动时自动为样本表补充片段相关列）。

示例：`examples/reference.txt`（全长 11 bp）+ `examples/fragment_F2.txt`
（片段 `ACGTGC`，反向唯一匹配全长 6-11）+ `examples/sample_F4.tsv`
（按片段编号：第 4 位 SNP、第 2 位插入，换算后分别为全长 `8:A>T` 与 `9:C>CTT`）。

## 关键规则

### 归一化（参考左对齐）

采用经典 left-align 流程（与 `bcftools norm` / `vt normalize` 等价）：

1. 去除 REF/ALT 共同后缀；
2. 无法去尾时整体左移一位并补参考前缀碱基，循环直到不能移动；
3. 在参考起点出现空等位基因时回退到最后一个合法带锚状态；
4. 去除共同前缀（每个等位基因至少保留 1 个锚碱基）。

因此重复序列中的等价写法（如 `GCTTTGC` 上 `(3,T,TT)`、`(4,T,TT)`、`(5,T,TT)`）
都会归一化为同一个规范键 `(2,C,CT)`，从而被识别为同一变异。

### 事务与一致性

- 同一样本归一化后出现重复变异（同一规范键）→ **整份文件拒绝**，不写入任何数据。
- 任何校验错误（REF 不符、非法 GT、类型不支持、格式错误等）都在事务内失败回滚，
  **错误上传不改变当前结果**。
- 同名样本重传 = 替换：新文件完整校验通过后，旧变体在同一事务中删除，旧变异不再计数。
- 更换参考 = 在一个写事务内插入新参考并**重验全部样本**：
  REF 不符或归一化后重复的样本标记为 `NEEDS_REUPLOAD`（待重传）、变体删除、
  从汇总剔除；修正后重新上传即恢复。
- 所有写事务使用 `BEGIN IMMEDIATE` 立即取 SQLite 写锁，使样本上传与参考更新
  严格串行；页面读取使用快照事务，因此样本上传与参考更新交错时，页面只会展示
  **同一版参考下的完整汇总**，不会出现跨版本混算。

## 目录结构

```
app/
  __init__.py        # Flask 工厂与路由
  normalization.py   # 纯函数：解析、校验、左对齐归一化（无 Flask 依赖）
  db.py              # SQLite 连接、WAL、事务、建表
  services.py        # 上传/重验/替换/汇总业务逻辑
  templates/         # Jinja2 页面
  static/style.css
tests/               # unittest：归一化单测、随机性质测试、端到端集成测试
docker/entrypoint.sh
Dockerfile
docker-compose.yml
```

## 测试

```bash
python -m unittest discover -s tests -v
```

- `test_normalization.py`：解析、边界、等价变异左对齐、重复拒绝等
- `test_properties.py`：4000 个随机变异，验证「单倍型保持」「同事件同规范键」
- `test_fragment.py`：片段定位（唯一/无匹配/不唯一）、反向换算与左锚边界、
  随机单倍型保持性质、片段上传/重传/换参考重验的端到端流程、旧库迁移
- `test_app.py`：Flask 端到端流程（上传、替换、换参考重验、错误隔离、删除）

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 参考信息、上传表单、样本列表、规范变异汇总 |
| POST | `/reference` | 上传/更换参考（multipart 字段 `reference`） |
| POST | `/samples` | 上传/重传样本（字段 `name`、`sample`，可选 `fragment` 片段参考） |
| POST | `/samples/<id>/delete` | 删除样本 |
| GET | `/variants/<pos>/<REF>><ALT>` | 变异详情：样本、GT、片段位置与方向、TSV 原记录 |
| GET | `/healthz` | 健康检查 |
